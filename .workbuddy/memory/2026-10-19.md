## 修复：APP/H5 访问他人主页时导航栏标题错显「我的主页」

### 根因
`pages/community/profile.vue` 同时承载「自己主页」（无参）和「他人主页」（`?id=xxx`，
入口：community/detail.vue、tabbar/community.vue、community/search.vue、user/follow-list.vue），
但 `pageTitleKey` 被写死为 `pageTitle.communityProfile`（=「我的主页」），
mixin 在 mounted 统一写入原生 navbar，导致他人主页也显示「我的主页」。

### 改动
1. `src/utils/i18nPageMixin.js`：`resolvePageTitle(key, fallback, ctx)` 新增 ctx，
   函数式 pageTitleKey 用 `key.call(ctx)` 调用；`_applyPageTitle()` 传 `this`。
   原因：自定义顶层选项不会被 Vue 自动 bind，原实现 `key()` 里读不到 `this.isOwnProfile`。
2. `src/pages/community/profile.vue`：
   - `pageTitleKey()` 改为方法：`isOwnProfile ? 'pageTitle.communityProfile' : 'pageTitle.communityUserProfile'`
   - onLoad 解析出 viewedUserId 后立刻 `this._applyPageTitle()`（提前于 mounted，减少 pages.json 默认标题闪现）
   - 顺带加固：`decodeURIComponent(query.name)` 加 try/catch（昵称含裸 `%` 会抛 URIError 中断整个 onLoad）
3. `src/i18n/zh-CN.js` + `en-US.js`：新增 `pageTitle.communityUserProfile`（TA的主页 / User's Profile）

### 验证
- `@vue/compiler-sfc` parse/compileScript/compileTemplate 均 OK；esbuild transform 三个 js OK
- 用 `createRenderer` 假渲染器跑真 Vue 运行时：own → 「我的主页」，other → 「TA的主页」（证明 $options 保留函数且 call(this) 能读 computed）
- `uni build -p app` 成功（2m6s），`dist/build/app/app-service.js` 含新文案

### 备注
- `pages/user/user-profile-page.vue` 是另一个「他人主页」入口（标题「用户主页」，normal），未受影响
- 未改 `pages.json` 的 `navigationBarTitleText: 我的主页`（onLoad 已提前覆盖，避免影响自己主页首帧）

## 修复：商品详情「取消收藏」假成功（提示成功但刷新后仍在）

### 根因（后端参数绑定位点错）

- 后端 `FavoriteController#removeFavorite` 当时只声明 `@RequestBody FavoriteRequest`，query 完全没读 →
  `productId=null` → `delete where user_id=? and product_id is null` → 删 0 行 → 仍 `Result.success()`
- 前端乐观更新 UI + 收到 200 → 提示成功；刷新后 `getFavorites()` 又渲染回来
- 日志实证：`14:33:50 ← [DELETE] /api/v1/favorites?productId=... → 200 (860ms)`，库里记录仍在

### 改动

2. `FavoriteServiceImpl`：productId 为空抛 `IllegalArgumentException`（→400），删 0 行 warn、N 行 info
3. `app/src/pages/goods/detail.vue`：收藏状态判断 `Number()===Number()` → `String()===String()`（雪花 ID 19 位超 2^53）

### 验证（真实环境）

## 修复：商品详情主图不能左右滑动

### 根因
`pages/goods/detail.vue` 的 `<swiper>` 上写了 `:disable-touch="true"`。
uni-h5 源码 `uni-h5.es.js:15508-15511` 的 `useTouchtrack` 回调首行就是
`if (props.disableTouch) return;` —— 触摸起点被直接丢弃，整条滑动链路不启动，
主图只能用缩略图切换。（APP 端原生 swiper 同样按该属性禁用）

### 改动
- 移除 `:disable-touch="true"`，并加注释禁止重新加回
- 指示点颜色 `var(--brand-500)` / `var(--background-400)` → `#dbc98a` / `#d1ccc4`：
  APP 端 swiper 是原生组件，`indicator-*-color` 走原生参数传递，不解析 CSS 变量
- 商品 2105169632819970050 实测有 4 张图（`GET /api/v1/products/{id}` → images 4 条），排除"只有一张图"

### 验证
- `uni build -p app` 成功（1m57s）
- 产物 `dist/build/app/app-service.js`：`disableTouch` 仅剩 1 处（uview-plus `columnNotice` 默认配置，与详情页无关），`dbc98a` 已出现

## 修复：意见反馈「提交不真实」+ 新增后台查看页

### 现象
App `pages/user/feedback` 界面完整但点提交无效果；后台没有查看意见反馈的入口。

### 根因（5 个，全部实测复现）
1. **类型枚举不匹配**：前端传 `feature/ux/content/other`，后端 `@Pattern` 只认 `BUG|SUGGEST|COMPLAINT|OTHER` → 400
2. **字段名不匹配**：前端传 `description`，后端 DTO 要 `content` → `@NotBlank` 失败 → 400
   （实测返回：`type: 反馈类型必须是...; content: 反馈内容不能为空`）
3. **images 写入 json 列格式非法**：`String.join(",", images)` → `"/a.jpg,/b.jpg"` 写 `mo_feedback.images`（json 列）→ 409
4. **截图是本地临时路径**：`chooseImage` 的 `tempFilePaths` 直接当 URL 提交，从未上传，即使入库也是死链
5. **净化把中文转成 HTML 实体**：`XssSanitizer.sanitizeRichText/PlainText`（OWASP）把 `，`→`&#xff0c;`、`@`→`&#64;`，
   存入纯文本字段后，uni `<text>` 与 Vue `{{ }}` 都不解析实体 → 两端显示乱码

### 改动
**后端**
- `FeedbackSubmitRequest`：正则放宽为 `(?i)^(BUG|SUGGESTION|SUGGEST|COMPLAINT|OTHER|FEATURE|UX|CONTENT)$`（兼容旧客户端）
- `FeedbackServiceImpl`：新增 `normalizeType()`（FEATURE/UX/SUGGEST→SUGGESTION，CONTENT→COMPLAINT，非法抛 400）；
  content/contact 改用新增的 `XssSanitizer.sanitizeText()`（不去实体转义）
- `FeedbackController`：images 用 ObjectMapper 序列化为 JSON 数组，并逐个 `sanitizeUrl` 白名单过滤
- `XssSanitizer`：新增 `sanitizeText()`（去控制字符 + trim，不转义），并给 `sanitizePlainText` 补警告注释
- `FeedbackEntity`：补 `replyTime` / `updateTime`
- 新增 `AdminFeedbackService` + `AdminFeedbackServiceImpl` + `AdminFeedbackController`（`/api/admin/feedback`）：
  `/stats`、`/list`（status/type/keyword + 分页，批量补用户昵称邮箱）、`/{id}`、`PUT /{id}`（状态 + 回复，写 replyTime）

**App**
- `pages/user/feedback.vue`：选项值改标准枚举、提交字段 `content`、截图先 `uploadApi.uploadImages()` 再提交、
  内容 ≥10 字前端校验、catch 不再重复 toast
- i18n 新增 `feedback.descTooShort` / `feedback.uploading`（zh/en）

**管理端（moyuyo-server/moyuyo-admin）**
- `api/admin.js`：新增 getFeedbackList / getFeedbackDetail / handleFeedback / getFeedbackStats
- 新增 `views/FeedbackManage.vue`（KPI + 筛选 + 服务端分页表格 + 详情弹窗含截图预览/状态/回复）
- `router/index.js` 加 `/feedback`；`AdminLayout.vue` 「运营工具」组加「意见反馈」菜单

### 验证（真实环境）
- `mvn compile` 通过；`npm run build`（管理端）通过；`docker compose build app` 通过，容器 healthy
- 提交实测：`POST /api/v1/feedback {type:BUG, content:"…，…（iOS 17）", images:["/uploads/…"]}` → 200，
  落库 content 保留中文标点、`images` 为 `["/uploads/2026/10/16/aaa.jpg"]`
- 管理端实测：登录 → `/stats` `{total:1,pending:1}` → `/list` 返回 nickname/email → `/{id}` images 数组 →
  `PUT /{id} {status:RESOLVED, replyContent:…}` → 200 且 `replyTime` 有值
- `/admin/` 200，`FeedbackManage-CET9XUmq.js` 200；测试数据已按 id 清除（mo_feedback 现为 0 条）
